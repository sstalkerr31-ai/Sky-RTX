# 🌌 SkyRT — аппаратная трассировка лучей для *Sky: Children of the Light*

> **Статус:** 🛠️ экспериментальный, активно развивается. Только ПК · Vulkan · NVIDIA RTX (аппаратный `ray_query`). Проверено на одном ПК (RTX 5070 Ti).
>
> **Это ещё не полная трассировка пути.** Лучи уже знают цвет поверхностей за кадром и освещают их с одним отскоком, подробнее в разделе [Трассировка пути: где мы на самом деле](#-трассировка-пути-где-мы-на-самом-деле).

SkyRT — это **неявный слой Vulkan**, который добавляет в *Sky: Children of the Light* настоящую аппаратную трассировку лучей **без изменения файлов игры**. Каждый кадр он собирает сцену в структуры ускорения, трассирует лучи по реальной геометрии и подмешивает результат в HDR-изображение игры до постобработки. В комплекте небольшая **панель управления** (установка в один клик, настройки на лету, запуск игры).

## ✨ Возможности

| Возможность | Состояние |
|---|---|
| Мягкие **лучевые тени от солнца** (полутень зависит от размера солнца) | ✅ |
| **Персонажи отбрасывают плавные и точные тени** (скелетные меши получают свою BLAS каждый кадр) | ✅ |
| Лучевое **затенение в щелях (AO)** и один отскок света (**GI**) с передачей цвета | ✅ |
| **Шумоподавление**: билатеральное размытие + накопление по кадрам (репроекция, отсечение по глубине, ограничение дисперсии) | ✅ |
| Направление солнца берётся из игры, выбросы между сценами отсекаются | ✅ |
| Принудительная **анизотропная фильтрация** (16x) и настройка резкости (LOD bias) | ✅ |
| Установщик в один клик и панель с настройками на лету | ✅ |
| Несколько инстансных объектов в структуре лучей | 🧪 эксперимент, эффект небольшой |
| Отражения воды и льда | 🧪 эксперимент: шейдеры найдены, отражение написано, но на настоящей воде его ещё никто не подтвердил |
| Трава в структуре лучей (тени, AO) | 🧪 эксперимент |
| **Материалы для лучей**: геометрия связана со своим цветом (текстуры или цвет из параметров отрисовки) | 🧪 новое, по умолчанию выключено (`matalbedo=1`) |
| **Свет в точке попадания**: для попаданий за кадром считаются солнце, N·L, луч тени и окружающий свет | 🧪 новое, один отскок, по умолчанию выключено |
| Свет от костров, свечей и ламп с лучевыми тенями | ✅ (новое, настраивается) |
| Несколько отскоков света (GI) | ✅ (новое, настраивается) |

## 🥇 Чем SkyRT отличается

На октябрь 2026 мы **не знаем других публичных проектов с аппаратной трассировкой лучей для Sky** (искали на GitHub, Nexus Mods и в сети). Всё, что есть сейчас, это пост-обработка:

| | ReShade / «RTGI»-пресеты | **SkyRT** |
|---|---|---|
| Лучи трассируются по | буферу глубины (экранное пространство) | **реальной геометрии сцены (BLAS/TLAS)** |
| Тень от того, что вне экрана или за стеной | ❌ | ✅ |
| Тени движущихся персонажей | ❌ | ✅ |
| Использует RTX-железо (`ray_query`) | ❌ | ✅ |
| Изменяет файлы игры | нет | нет |

NVIDIA RTX Remix не подходит: он рассчитан на игры DirectX 8/9 с фиксированным конвейером. Если знаешь другой проект с аппаратными лучами для Sky, открой issue.

## 🚀 Быстрый старт

**Требования:** Windows 10/11 · видеокарта NVIDIA RTX с актуальными драйверами (проверено только на RTX 5070 Ti; теоретически подойдёт любая карта с `VK_KHR_ray_query` и `VK_KHR_acceleration_structure`) · *Sky: Children of the Light* для ПК.

1. **Скачай `SkyRT_Setup.exe`** из [свежей сборки](../../releases/tag/latest). Это один файл: установка, настройки и запуск.
2. **Запусти его**, и помощник Лучик поставит лучи. Слой ляжет в `%LOCALAPPDATA%\SkyRT` и зарегистрируется только для твоего пользователя Windows; права администратора не нужны. На рабочем столе появится ярлык.
3. **Нажми «Играть с лучами».** Если игра не нашлась, один раз покажи установщику `Sky.exe`.

Готово. В игре нажми **Ctrl+Home**, чтобы сравнить картинку с лучами и без.

**Обновления приходят сами.** Каждое изменение в этом репозитории GitHub собирает и выкладывает в [свежую сборку](../../releases/tag/latest). При запуске установщик один раз проверяет её и, если есть новое, Лучик предлагает обновиться («Обновить» / «Потом» / «Не напоминать об этой»). Он никогда не настаивает, ставит только файл с совпавшей SHA-256 и не трогает настройки (`SkyRT.cfg`). Нет интернета — ничего страшного, остаётся то, что стоит.

> Слой загружается только для игры, запущенной кнопкой «Играть с лучами» (она ставит `SKYRT_ENABLE=1` для этого процесса). Другие Vulkan-программы не затрагиваются.
> Для запуска через Steam установщик скопирует строку в параметры запуска: Sky → Свойства → Параметры запуска.

**Настройки** — в установщике («Настройки»); всё применяется сразу, даже пока игра запущена.
**Удаление:** открой установщик → «Удалить».

## 🎛️ Панель управления

| Вкладка | Что делает |
|---|---|
| **Игра** | Статус файлов / слоя / пути к игре · *Установить* / *Удалить* · путь к `Sky.exe` · **Играть с лучами** · Играть без лучей · переключатель языка (RU/EN) |
| **Графика** | Пресеты (Низкий / Средний / Высокий / Ультра / Свой) и ползунки на каждую настройку. Любое изменение записывается в `SkyRT.cfg` и применяется **на лету**, пока игра запущена |
| **Лог** | Свежий `SkyRT_*.log` с автообновлением и кнопкой *Открыть папку*. Этот файл прикладывай к сообщениям об ошибках |

Пресеты: **Низкий** 1 луч теней / 2 луча AO, без GI · **Средний** 2 / 4 (по умолчанию) · **Высокий** 4 / 6, дальность GI 40 · **Ультра** 8 / 8, до 24 накопленных кадров, дальность GI 60.

## ⚙️ Справочник по настройкам

Всё, что меняет панель, лежит в `%LOCALAPPDATA%\SkyRT\SkyRT.cfg` (обычные строки `ключ=значение`, файл перечитывается примерно раз в секунду). Можно править руками.

> **О значениях по умолчанию.** Стандартные значения подобраны разработчиком под свой вкус, экран и ПК. Это отправная точка, а не правило: меняй любые на своё усмотрение (ползунки панели или файл руками). Мод ещё в активной разработке, настройки могут меняться от версии к версии.

| Ключ | Диапазон | Что значит |
|---|---|---|
| `enabled` | 0/1 | Лучи вкл/выкл (0 = оригинальная картинка) |
| `shadows` · `strength` · `sunsize` · `shrays` | 0/1 · 0–1 · 0–10° · 1–8 | Тени: вкл/выкл, тёмность, размер полутени, лучей на пиксель |
| `ao` · `aostrength` · `aoradius` · `aorays` | 0/1 · 0–1 · 0.05–20 · 1–8 | AO: вкл/выкл, сила, радиус (в единицах мира), лучей на пиксель |
| `gi` · `gistrength` · `girange` | 0/1 · 0–2 · 1–200 | Отражённый свет: вкл/выкл, сила, как далеко смотрят лучи |
| `taa` · `taan` | 0/1 · 1–64 | Накопление по кадрам: вкл/выкл, максимум кадров (меньше = меньше шлейфов, больше шума) |
| `dyngeo` | 0/1 | Персонажи и анимированные меши отбрасывают лучевые тени |
| `instgeo` | 0/1 | Мелкие инстансные объекты в структуре лучей (эксперимент) |
| `deep` | 0/1 | **Режим глубоких отскоков**: каждый луч отскакивает несколько раз, с точными нормалями поверхностей. Нужна видеокарта с ray tracing position fetch (RTX 30xx и новее; в логе будет видно, если нет). Очень тяжело, GPU греется намеренно. Клавиша Ctrl+] |
| `bounces` | 1..8 | Отскоков на луч в глубоком режиме (по умолчанию 3). Чем больше, тем тяжелее. Клавиши Ctrl+Вверх / Ctrl+Вниз |
| `pathtrace` | 0/1 | Режим скриншота: в 4 раза больше лучей, накопление до 256 кадров, глубже отскоки. Несмотря на имя ключа, материалов сам по себе не добавляет. Клавиша Ctrl+Backspace |
| `ptadapt` | 0/1 | 1 = режим скриншота работает в полном качестве только при неподвижной камере; 0 (по умолчанию) = всегда в полном |
| `grass` | 0/1 | Трава в структуре лучей: отбрасывает тени и участвует в AO (эксперимент) |
| `gimulti` | 0–0.9 | Многократные отскоки света: каждый кадр добавляет ещё один отскок (нужен `taa=1`); 0 = один отскок |
| `light` | 0/1 | Свет от огня, свечей и ламп: очень яркие пиксели кадра становятся источниками света, которые освещают и затеняют окружение (новое, требует проверки) |
| `lightstrength` · `lightrange` | 0–200 (по умолчанию 2) · 1–60 | Яркость света и дальность одного источника (в единицах мира) |
| `lightmax` | 0.05–5 | Мягкий потолок света, добавляемого в одну точку (меньше = без пересвета) |
| `lightthr` · `lightrays` · `lightdebug` | 0.3–50 · 1–4 · 0/1 | Порог яркости, с которого пиксель считается источником (лог пишет самый яркий пиксель), теневых лучей на пиксель, покрасить найденные источники розовым |
| `matalbedo` | 0/1 | **Материалы и свет в точке попадания.** Должно стоять 1 в файле **до запуска игры** (текстуры отслеживаются с первого кадра), дальше Ctrl+F9 переключает на лету. В панели пока нет |
| `matgain` | 0–8 | Яркость света от поверхности попадания (по умолчанию 1) |
| `matbaked` | 0/1 | Читать запечённый свет из вершин в точке попадания (по умолчанию 1, работает только с материалами). Поставь 0, если при включённых материалах игра падает с `DEVICE_LOST` |
| `texprobe` | 0/1 | Только лог: какие текстуры читает каждая пара шейдеров. Ставить до запуска игры |
| `waterfx` · `waterrefl` · `glint` | 0/1 · сила · 0/1 | Экспериментальная вода и лёд: отражения вкл/выкл, сила отражения, блики солнца |
| `aniso` · `lodbias` | 0–16 · −2…1 | Анизотропная фильтрация, сдвиг резкости текстур (**применяется при следующем запуске игры**) |
| `autosun` · `az` · `el` | 0/1 · 0–360° · 1–89° | Брать солнце из игры или задать вручную |
| `view` | 0–10 | Режимы отладки. 0 = обычная картинка, 5 = только отражённый свет, 8 = цвет материала в каждом пикселе (чёрное = нет материала), 9 = отражённый свет, где каждый луч с материалом красный, 10 = запечённый свет из вершин (чёрное = нет данных вершин) |

Больше лучей = меньше шума, но больше работы для видеокарты. Sky обычно упирается в процессор, так что у GPU, как правило, большой запас.

## ⌨️ Горячие клавиши в игре

| Клавиши | Действие |
|---|---|
| **Ctrl+Home** | Лучи вкл/выкл (сравнение с оригиналом) |
| **Ctrl+End** | Отладка: перепись шейдеров. Первое нажатие начинает запись основного прохода, второе печатает в лог все пары шейдеров со счётчиком отрисовок (для поиска шейдеров воды и льда). Старые режимы отладки выбираются `view=N` в конфиге |
| **Ctrl+]** | Режим глубоких отскоков вкл/выкл (очень тяжело) |
| **Ctrl+Вверх / Ctrl+Вниз** | Отскоков +1 / −1 (1..8) в глубоком режиме |
| **Ctrl+Backspace** | Режим скриншота вкл/выкл: в 4 раза больше лучей, долгое накопление. Для чистой картинки стой на месте |
| **Ctrl+F9** | Материалы вкл/выкл. Нужен `matalbedo=1` при запуске игры. Эффект бывает слабым: встань на месте и сравни два скриншота |

Если картинка выглядит странно, поставь `view=0`.

## 🧯 Проблемы и вопросы

**Ничего не меняется / картинка как в оригинале.**
Проверь панель: *Слой Vulkan* должен быть «установлен», а игра запущена кнопкой **Играть с лучами**. Открой вкладку **Лог**: при старте игры должен появиться свежий `SkyRT_*.log`. Нет лога значит слой не загрузился (не тот лаунчер, не задан `SKYRT_ENABLE`).

**Игра не запускается из панели.** Панель запускает `Sky.exe` напрямую. Если твоей версии нужен Steam или другой лаунчер, запусти игру там с переменной окружения `SKYRT_ENABLE=1`. В параметрах запуска Steam пиши `cmd /c "set SKYRT_ENABLE=1&& %command%"`, без пробела перед `&&` (иначе пробел попадёт в значение).

**Странные цвета / чёрный мир.** Поставь `view=0`. Если не помогло, поставь `enabled=0` и пришли лог.

**Низкий FPS.** Выбери пресет *Низкий* или уменьши `shrays` / `aorays`. Для проверки отключи `instgeo` и `dyngeo`.

**Шлейфы за персонажами / при быстрой камере.** Уменьши `taan` (попробуй 6).

**Света от огня нет или светятся обычные поверхности.** Поставь `lightdebug=1`: пиксели, которые считаются источниками, станут розовыми. Если у костра ничего розового нет, уменьши `lightthr`; если розовая освещённая солнцем земля, увеличь. В `SkyRT_*.log` каждые несколько секунд пишется самый яркий пиксель (`rt: emissive lights: ...`).

**Ctrl+F9 ничего заметно не меняет.** Проверь в логе строки `rt: KEY Ctrl+F9` и `rt: material coverage`. Затем поставь `view=9`: если мир стал красным, материалы доходят до лучей, а эффект просто слаб в этой сцене. Сильнее всего он там, где окружение за кадром отличается по цвету от того, что видно на экране.

**Тени прыгают при смене сцены.** Направление солнца сглаживается, при настоящей смене сцены переход занимает около секунды.

**Вылет или зависание.** Открой issue и приложи свежий `SkyRT_*.log` (вкладка Лог → *Открыть папку*). Если в конце лога нет строки «clean shutdown», значит, игра упала.

**Windows SmartScreen / антивирус ругается на `SkyRT_Panel.exe` / `SkyRT.dll`.** Файлы не подписаны, а DLL, которые перехватывают графические API, часто попадают под эвристику. Всё можно собрать самому из этого репозитория.

**Это безопасно для моего аккаунта?** Слой не трогает файлы и память игры и ничего никуда не отправляет, но это неофициальная модификация клиента онлайн-игры. Используй на свой риск.

**Работает на AMD / Intel?** Не проверено. Теоретически подойдёт любая карта с `VK_KHR_ray_query` и `VK_KHR_acceleration_structure`.

## 🛠️ Сборка из исходников

Нужно: Visual Studio (C++ x64). Заголовки Vulkan лежат в `third_party/vulkan`, поэтому Vulkan SDK нужен только для пересборки шейдеров.

```bat
:: открой "x64 Native Tools Command Prompt for VS", затем:
installer\build.bat             :: -> installer\build\SkyRT.dll и SkyRT_Setup.exe (слой внутри exe)
```

`set SKYRT_CHANNEL=test` перед сборкой — установщик будет брать обновления из релиза `test` (по умолчанию `latest`).
GitHub делает то же на каждый пуш (`.github/workflows/build.yml`): `main` → релиз **latest**, `installer` → пре-релиз **test**, в каждом `SkyRT.dll`, `SkyRT_Setup.exe` и `update.json` (SHA-256 обоих). Ручные релизы не нужны.
Сборка воспроизводимая (`/Brepro`), поэтому установщик точно понимает, стоит ли текущая версия.
Тестовые ключи установщика: `--root <папка> --selftest` (поставить/проверить/удалить в тестовой папке), `--updtest` (спросить GitHub, ответ в `updtest.txt`), `--demo`.
Ручная установка без установщика: `layer\install.ps1` регистрирует слой (`-Uninstall` удаляет). Старая Python-панель (`panel/`) работает, но больше не развивается.

После правки шейдера `.comp`: `glslangValidator -V --target-env vulkan1.2 layer\rt_fx.comp -o rtfx.spv`, затем `python tools\spv2h.py rtfx.spv layer\rtfx_spv.h kRtFxSpv rt_fx.comp`.

| Исходник | Заголовок | Массив | Назначение |
|---|---|---|---|
| `rt.comp` | `rt_spv.h` | `kRtSpv` | проход трассировки для видеокарт без position fetch |
| `rt.comp` с `-DPOSFETCH` | `rtpf_spv.h` | `kRtPfSpv` | тот же проход с настоящими нормалями попадания |
| `rt_mat.comp` | `rtmat_spv.h` | `kRtMatSpv` | средний цвет материала |
| `rt_deep.comp` | `rtdeep_spv.h` | `kRtDeepSpv` | вариант с глубокими отскоками |
| `rt_fx.comp` | `rtfx_spv.h` | `kRtFxSpv` | шумоподавление и подмешивание |
| `rt_light.comp` | `rtlight_spv.h` | `kRtLightSpv` | поиск светящихся пикселей |
| `rt_lmerge.comp` | `rtlmerge_spv.h` | `kRtLMergeSpv` | устойчивый список источников света |

После правки `rt.comp` пересобирай **оба** заголовка: `rt_spv.h` и `rtpf_spv.h`. Бери исходники из этого репозитория: перед пересборкой шейдер должен совпадать со своим заголовком.

## 🧭 Трассировка пути: где мы на самом деле

SkyRT не заменяет рендер игры. Он трассирует лучи по настоящей сцене и добавляет свет к картинке самой игры.

| Этап | Состояние |
|---|---|
| Лучи по настоящей геометрии | ✅ |
| Попадание на экране: цвет берётся из кадра | ✅ |
| Попадание за кадром: настоящий цвет поверхности | 🧪 один средний цвет на материал или отрисовку, без UV |
| Свет в точке попадания: солнце, N·L, луч тени | 🧪 один отскок, в `rt.comp` |
| Свет в точке попадания: окружающий свет | 🧪 запечённый свет из вершин у `RockFaceShMesh`, у остальных один общий цвет |
| Материалы в режиме глубоких отскоков | ❌ `rt_deep.comp` пока использует старый запасной цвет |
| Персонажи и анимированные меши как поверхности отскока | ❌ материала пока нет |
| Замена собственного освещения игры | ❌ пока не планируется |

С материалами земля рядом с синей скалой заметно перенимает её цвет: примерно в 1.25 раза синее в первом замере и в 1.6–2.3 раза в более яркой сцене при `gistrength=1`, что уже слишком сильно. При обычном `gistrength=0.3` картинка выглядит естественно. В проверенных сценах материал был примерно у 55–60% кэшированных треугольников.

## 🧩 Архитектура

- Слой включает на устройстве игры `VK_KHR_acceleration_structure`, `VK_KHR_ray_query`, `VK_KHR_deferred_host_operations` и адреса буферов.
- Запоминаются отрисовки основного прохода (вершинные/индексные буферы, пайплайн, indirect-аргументы). Статическая геометрия кэшируется в кольце слотов BLAS; геометрия в буферах, которые пишет CPU (скелетные персонажи), и несколько инстансных объектов каждый кадр пересобираются в динамическую BLAS. Всё вместе попадает в один TLAS.
- После основного прохода запускаются четыре вычислительных прохода: `rt_light.comp` (находит яркие светящиеся пиксели по плиткам экрана), `rt_lmerge.comp` (сливает их в небольшой устойчивый список источников, которые плавно появляются и гаснут, чтобы свет не мигал), `rt.comp` (лучи теней, AO и отражённого света через `ray_query`) и `rt_fx.comp` (билатеральное размытие, накопление по кадрам, подмешивание в цветовое изображение).
- **Выбор пайплайна трассировки:** при наличии `VK_KHR_ray_tracing_position_fetch` проход использует `rtpf_spv.h` и получает настоящие нормали треугольника; без него используется `rt_spv.h`, где N·L принимается за 0.5. Вторая ветка ни разу не запускалась.
- **Отслеживание материалов** (только при `matalbedo=1` на старте): слой запоминает, какие наборы дескрипторов и динамические смещения привязывает каждая отрисовка. Кэшированная геометрия получает номер материала одним из двух способов:
  - *Материалы с текстурами* (`MeshSh`, `MeshShSl`, `MeshSlDarkvine`, таблица `kMatFs`): цвет = текстура `s1.b8` × `s1.b9`. `rt_mat.comp` усредняет пару один раз, в том кадре, который её нарисовал, поэтому текстуры точно живы.
  - *Цвет из параметров отрисовки* (`RockFace*`, `GrassSh`, `SandSh`, таблица `kMatVs`): у этих шейдеров нет цветной текстуры. Цвет лежит как `vec3` в блоке отрисовки (set 0, binding 0) и читается из отображённой памяти при записи команд. Для скал и травы это подтверждено по декомпилированным вершинным шейдерам; два смещения песка до итогового цвета ещё не прослежены.
- **Таблица «геометрия → материал»:** SSBO с секцией на каждый слот AS, индекс `слот × 30000 + номер геометрии`. Пишется при пересборке слота, когда он не используется кадрами в работе. Цвета лежат во втором SSBO с шагом 256 байт.
- **Доступ к вершинам в точке попадания:** шейдер трассировки читает индексный и атрибутный буферы игры напрямую по адресам (`GL_EXT_buffer_reference`, таблица `GeoV` на binding 13). Он находит треугольник попадания, читает три вершины и смешивает их по барицентрическим координатам. Буферы атрибутов защищены от удаления так же, как данные BLAS; если любой кэшированный буфер исчезает, чтение вершин отключается до следующей пересборки. Пока разобран только `RockFaceShMesh`. `matbaked=0` выключает это чтение.
- **Окружающий свет в точке попадания:** настоящий окружающий свет игры запечён в вершинах (`loc2`, `loc3`) и дополняется глобальной частью (UBO кадра +1184). Кубическая карта добавляет только мелкие детали, поэтому здесь не используется.
- **Свет в точке попадания** (`rt.comp`): попадания на экране берут цвет из кадра. Попадание за кадром с материалом получает `albedo × (цвет солнца × N·L × луч тени + окружающий свет) × matgain`, значения берутся из UBO кадра самой игры (цвет солнца +912, окружающий +944). Окружающий свет берётся из вершин, где их можно прочитать, иначе это общий цвет. У шейдера скал формула той же формы, поэтому масштаб совпадает с кадром.
- **Без материала** остаётся старый запасной вариант: половина цвета текущего пикселя.
- **Подмешивание** (`rt_fx.comp`): `цвет += оттенок поверхности × отскок`, до тональной компрессии и блума игры.
- Слой опирается на такие факты об игре: обратная глубина (reverse-Z), ось y вверх, UBO кадра на 1584 байта (матрица вида-проекции, камера, направление света, цвет солнца). Шейдеры опознаются по хэшам FNV-1a их SPIR-V, поэтому обновление игры может незаметно выбить их из таблиц.

- [x] Слой Vulkan, доступ к HDR и глубине, извлечение матриц
- [x] BLAS/TLAS, тени через `ray_query`, динамическая геометрия (персонажи)
- [x] AO + отражённый свет, шумоподавление, накопление по кадрам
- [x] Установщик в один клик и панель управления

- [ ] Подтвердить отражения на настоящей воде и льду
- [x] Чтение вершин в точке попадания, запечённый свет для `RockFaceShMesh`
- [ ] Запечённый свет для остальных шейдеров

Известные ограничения: статическая геометрия считается неподвижной; объекты, анимируемые на GPU (ветер, волны), не отражаются в тенях; эффекты вставляются до тональной компрессии и блума игры; прозрачность (облака, вода, частицы) не решена; обновление игры может изменить хэши шейдеров.
